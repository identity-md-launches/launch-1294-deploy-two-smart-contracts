# Sepolia launch adaptation

## Scope and unchanged launch inputs

This is the supplied `sepolia` project, adapted for the approved `evm_contracts` launch. The factory deploys **Stacker, then ProjectRegistry**, with the existing constructor argument order (2 and 7 static arguments). Both constructors are nonpayable and need no initialization call. Neither application has an owner, admin, upgrade, pause, mint, or custody override. No token, pool, proxy, external library deployment, or new launch contract was added.

The existing `launch.json` is unchanged. Its Stacker uses TestIMD `0x2b69099e59b05901faa1dd164fabf098bf831e82` and TestSIMD `0xf9e2eec3b610ec6781f7438ac5fb4bc049d81cc1`. The registry uses the live Intake v2 `0xa43e6f75ee006411f79ac1c84120606c2330de82`, oracle payment token `0x44a1cd38474fb1748400e7deb5f8d786cce3f89a`, the new Stacker, and the supplied oracle signer. Bond remains 5 oracle test IMD; initial listing cooldown remains 3,600 seconds. These dependencies are reused, never redeployed. Application deployments and publication remain platform release steps.

`foundry.toml`, `foundry.lock`, `remappings.txt`, `.gitmodules`, `lib/`, package manifests and lockfiles, `.git/`, `.github/`, environment files and `node_modules/` were not modified. Existing compiler, optimizer, EVM version and `bytecode_hash = "none"` settings were preserved.

## Imported audit disposition

All five reports were investigated against the original code. Before source changes, four focused reproductions passed: three self-challenge cooldown cycles at a total cost of 1.5 oracle IMD; positive price rise blocking a challenge; permissionless application squatting; and the additional insufficient-signed-quorum case. Original project baseline was 68 passing tests and 7 optional fork skips.

1. **`24655b850bcaf56819106bd1c02f5aa071bc106d7ce9aedc250124a2d74c174c` — self-challenge cooldown:** reproduced. Removed renewed immunity after every defended challenge, the audit's ownerless option. Bond payment is deliberately unchanged. **Residual:** a one-open-request mechanism cannot guarantee fair ordering; repeated front-running can still win a request slot. This is a targeted removal of the cooldown amplification, not a claim that permissionless contention is solved.
2. **`20b2d38a7cb1ec69826ccfd8caf26bedf85359f63a75ac381a114c1c88355c26` — fixed oracle settings:** positive price failure reproduced and fixed by live lookup. **Residual:** retirement (`priceOf == 0`), Intake replacement, payment-asset replacement or signer rotation still require a new registry. The brief explicitly forbids an owner/admin, so the reference's owner-settable settings were not introduced. No unauthenticated replacement/rotation mechanism was invented. An old registry's listings must be cut off at a documented migration block by any future indexer, rather than remaining permanently eligible. Pending bonds retain their expiry path.
3. **`04f9947f13032b96914ecdcde381f1618f34d8db562c8467254f52c980e830d7` — open application slot:** reproduced and retained as the explicitly documented permissionless-design limit. Requiring `applicant == beneficiary` would not prove project authority and would not prevent a griefer naming itself. An ownership gate or concurrent-request redesign would change the approved “anyone applies” behavior without a defined authority model. The panel's beneficiary check, no-answer/expiry paths and rejection/reapplication behavior are preserved and tested.
4. **`63050a1a3408e2d7b603f65eea07252d00010d5934f4706e91145210370b9598` — missing protocol conformance coverage:** coverage gap confirmed and filled. A present ABI/digest mismatch did **not** reproduce: digest `0x95fefa8b7c529852f4e2b6aec888930eb2bf5078e6443a85808e36df19e1325c` and selector `0x510379c7` already match the protocol. No protocol library rewrite was needed.
5. **`0e0990499a40474ef79ae1134582f99b767240ec6dcc13fd265eadde012416d3` — different fee token:** confirmed correct existing wiring, not a contract defect. Approving/funding only the staking faucet token cannot fund an application. The site separately mints and approves the oracle asset; local contract and app tests cover failure with the wrong token and success with the proper one. Live Sepolia `priceOf(ACTION, 0x44a1…f89a)` was also read as `500000000000000000`.

## Independent review

A separate reviewer read the source changes, independently identified the missing signed-quorum check, validated its regression, and contributed the cold callback tests. A second pass reviewed site transactions, accounting and rendering. Two website issues were reproduced and fixed:

- A network check before calling the wallet left a race during confirmation. Every transaction now explicitly includes `chainId: 11155111`, and the offline app test inspects the emitted `eth_sendTransaction` request as well as blocking a deposit after an intervening network change.
- A successful unrelated receipt could be paired with an old contract and a late indexing start. Deployment validation now requires no code at the address one block before the declared deployment and code present at that block; an existing-address regression rejects this case.

The reviewer found no further concrete defect in the contract diff. This local review is evidence for the platform's full independent audit, not deployment approval.

## Verification and release boundaries

The following checks are run locally with the unchanged project configuration:

- `forge build`: passed. `forge test`: **94 passed, 0 failed, 7 optional fork tests skipped**, including unit, fuzz, stateful invariant, deployment, conformance and cold callback tests. This count excludes scratch files, which are not submitted.
- Supplied protected factory floor rehearsed locally using its exact code, compiled application bytecode, the existing manifest arguments and computed CREATE2 references. The scratch harness is removed after execution. **1 protected test passed**.
- `SEPOLIA_RPC_URL=https://ethereum-sepolia-rpc.publicnode.com forge test --match-contract 'RegistrySepoliaForkTest|SepoliaForkTest'`: four tests passed against the live Sepolia dependencies. These are local forks with mock signed settlement, not live oracle panel responses or broadcasts.
- `node --test site/test/core.test.mjs site/test/app.test.mjs`: **18 passed, 0 failed**, covering offline ABI, accounting, handoff, RPC and complete app transaction-flow checks. The shipped DOM and wallet are simulated; no private key is used.

Only the two production application runtimes are deployed: Stacker is 2,362 bytes, ProjectRegistry 19,490 bytes (both below EIP-170). Existing opcode scans reject DELEGATECALL, CALLCODE and SELFDESTRUCT. No Slither/Mythril claim is made.

Chrome was attempted with a clean temporary profile but aborts in macOS application registration before navigating. Consequently, responsive visual layout and a real extension-wallet smoke test remain unverified in this environment; `site/test/browser.mjs` is provided for an executable Chrome host. The DOM tests are not represented as a real browser test. Testnet transactions against the **new deployed addresses**, explorer verification and public URL publication necessarily follow the platform deployment. No keys were read, no live transactions were broadcast, and no release or GitHub publication was performed by this worker.

The page labels event-based totals as **listing points**: it filters listing periods but does not independently reconcile each credit with a project's trade logs or rate. That project-specific indexer is a production rewards requirement; no reward claim is made by the test site. All scan failures are marked unavailable/stale instead of fabricating zeroes or complete leaderboards.
